# รายงานเปรียบเทียบโมเดล (Model Comparison Report) สำหรับ NIDS

เอกสารฉบับนี้สรุปผลการทดลองปรับจูนพารามิเตอร์ (Hyperparameter Tuning) เพื่อค้นหาโมเดล Machine Learning และ Gradient Boosting ที่มีประสิทธิภาพสูงสุดสำหรับใช้เป็น **Baseline Model** ของระบบ Network Intrusion Detection System (NIDS)

## วัตถุประสงค์ของการเปรียบเทียบ
เพื่อรับมือกับปัญหาคลาสไม่สมดุล (Class Imbalance) ระหว่างข้อมูลการใช้งานปกติและข้อมูลการโจมตี การประเมินจะให้ความสำคัญกับค่าต่อไปนี้เป็นพิเศษ:
- **Recall (Macro):** สำคัญที่สุด เพราะเราไม่ต้องการให้ระบบปล่อยผ่านการโจมตีไปได้ (False Negatives ต่ำ)
- **F1-Macro:** ค่าเฉลี่ยแบบ Macro ระหว่าง Precision และ Recall เพื่อดูความสมดุลของทั้งสองคลาส
- **Precision (Macro):** เพื่อดูว่าการแจ้งเตือนของระบบมีความแม่นยำแค่ไหน และหลีกเลี่ยง False Positives ที่สูงเกินไป

## 🔍 วิเคราะห์เชิงลึก (In-Depth Analysis)

### 1. ความจำเป็นในการใช้ `scale_pos_weight`
เราจะสังเกตเห็นว่า Best Configuration ของ XGBoost, LightGBM, และ CatBoost **ล้วนเลือกใช้** `scale_pos_weight = 10`
สิ่งนี้ยืนยันสมมติฐานว่าข้อมูลมีความไม่สมดุลค่อนข้างสูง การให้น้ำหนักกับคลาสส่วนน้อย (Anomaly) มากขึ้น 10 เท่า ช่วยให้โมเดลหันมาสนใจที่จะตรวจจับการโจมตีได้ดีขึ้น ส่งผลให้ค่า **Recall** เพิ่มสูงขึ้นจากค่าเริ่มต้น (Default) อย่างก้าวกระโดด

### 2. กลุ่ม Gradient Boosting vs. Random Forest
* **Random Forest:** ใช้การถ่วงน้ำหนัก `class_weight='balanced'` ทำให้ได้ Recall อยู่ที่ประมาณ `0.818` ซึ่งถือว่ายอมรับได้ในระดับพื้นฐาน
* **Gradient Boosting (LGBM, XGB, CatBoost):** สามารถทะลุขีดจำกัดของ Random Forest ขึ้นมาได้อีกประมาณ 4-6% (ขึ้นไปแตะ `0.85` - `0.87`) เนื่องจากกลไกของ Gradient Boosting ที่เน้นแก้จุดที่ทายผิดในต้นไม้ต้นก่อนหน้า ทำให้สามารถจำแนกแพตเทิร์นการบุกรุกที่ซับซ้อนและทับซ้อนกับข้อมูลปกติได้ดีกว่า 

### 3. ระยะเวลาและทรัพยากรในการเทรน (Training Efficiency)
แม้ว่าจะไม่ได้มีการจับเวลาในระดับมิลลิวินาทีในตาราง แต่จากพฤติกรรมการเทรนที่พบ:
1. **LightGBM:** เร็วที่สุดและประหยัด RAM มากที่สุด แม้จะตั้งค่า `n_estimators=300` ก็ยังประมวลผลเสร็จได้อย่างรวดเร็ว
2. **CatBoost:** ช้ากว่า LightGBM แต่ใช้งานง่ายและมีประสิทธิภาพสูงมากในแง่ของผลลัพธ์
3. **XGBoost:** ให้ผลลัพธ์ที่ดี แต่อาจกินทรัพยากร (RAM/CPU) ในช่วงการจูนพารามิเตอร์ค่อนข้างสูง
4. **Random Forest:** กิน RAM สูงลิ่วเมื่อเทรนพร้อมกัน (จนเกิด Memory Error) และทำงานได้ช้ากว่า Gradient Boosting หากต้นไม้มีความลึกมาก

## 🚀 ข้อเสนอแนะ (Next Steps)

1. **เลือกใช้งาน LightGBM:** แนะนำให้แทนที่ Random Forest Baseline ด้วย LightGBM เป็นโมเดลหลักชั่วคราวในการพัฒนาเฟสต่อไป เนื่องจากทำความแม่นยำได้สูงสุดและกินทรัพยากรน้อย
2. **ปรับแต่ง (Fine-Tuning) รอบสอง:** ค่า `scale_pos_weight` ระหว่าง 10-20 เป็นช่วงที่มีประสิทธิภาพสูง เราอาจจะทำการทำ Grid Search หรือ Bayesian Optimization เฉพาะในช่วงที่แคบลงรอบ ๆ บริเวณนี้เพื่อดึงประสิทธิภาพให้สูงขึ้นอีก
3. **การคัดเลือกฟีเจอร์ (Feature Selection):** ลองนำฟีเจอร์ที่ไม่มีประโยชน์ออกเพิ่มขึ้น (จาก 50% เป็น 20-30%) เพื่อลดมิติข้อมูล ซึ่งอาจช่วยลดสัญญาณรบกวน (Noise) และทำให้ F1-Score ดีขึ้นได้อีก

## 🔄 ผลการประเมินด้วย 5-Fold Stratified Cross-Validation (บนชุดข้อมูล Train)

เพื่อยืนยันความเสถียรของ Best Configurations เราได้นำพารามิเตอร์ที่ดีที่สุดของทั้ง 4 โมเดลมาทดสอบด้วยเทคนิค **5-Fold Stratified Cross-Validation** บนชุดข้อมูล `KDDTrain+.txt` (แบ่งข้อมูลเป็น 5 ส่วน สลับกันเทรนและเทสต์เพื่อหาค่าเฉลี่ย) ผลลัพธ์แสดงให้เห็นถึงความทนทานต่อการ Overfitting ในข้อมูลชุดเดียวกัน:

| Model | Accuracy | Precision | Recall | F1 Score | Avg. Fit Time/Fold |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **LightGBM** | 0.9946 (±0.0003) | 0.9896 (±0.0004) | **0.9990** (±0.0003) | 0.9943 (±0.0003) | ~22.3s |
| **XGBoost** | 0.9946 (±0.0003) | 0.9900 (±0.0009) | 0.9985 (±0.0004) | 0.9943 (±0.0004) | ~32.3s |
| **CatBoost** | 0.9908 (±0.0006) | 0.9824 (±0.0009) | 0.9982 (±0.0004) | 0.9902 (±0.0006) | ~34.1s |
| **Random Forest** | **0.9988** (±0.0002) | **0.9991** (±0.0001) | 0.9982 (±0.0003) | **0.9987** (±0.0002) | **~17.0s** |

**📌 ข้อสังเกตสำคัญจากการทำ Cross-Validation:**
1. **เสถียรภาพสูงมาก (High Stability):** ค่าความแปรปรวน (±) ในแต่ละ Fold ต่ำมากในระดับทศนิยมตำแหน่งที่ 3-4 ซึ่งพิสูจน์ว่าพารามิเตอร์ที่เลือกมาไม่ได้ Overfit กับข้อมูลส่วนใดส่วนหนึ่งในชุด Train
2. **ประสิทธิภาพบน Distribution เดียวกัน:** สังเกตว่าคะแนนพุ่งขึ้นไปสูงถึงระดับ 0.99 (ต่างจากตารางสรุปด้านบนที่คะแนนอยู่ที่ 0.85-0.87) สาเหตุเป็นเพราะ *ตารางด้านบนวัดผลบน KDDTest+ ซึ่งมีการโจมตีรูปแบบใหม่ที่โมเดลไม่เคยเห็นมาก่อน (Zero-day)* แต่การทำ CV นี้เป็นการสุ่มแบ่งจากชุด KDDTrain+ ทำให้โมเดลเห็น Pattern ที่คล้ายคลึงกันในทุกๆ Fold
3. **ความสมดุลของ Gradient Boosting:** แม้ Random Forest จะได้คะแนน F1 และ Precision สูงสุดในการทดสอบนี้ แต่ **LightGBM ทำค่า Recall ได้สูงสุดถึง 0.9990** ซึ่งบ่งบอกว่า LightGBM เมื่อใช้ร่วมกับ `scale_pos_weight=10` มีความไวต่อการโจมตีสูงมาก (ปล่อยหลุดน้อยที่สุด) และยังใช้เวลาเทรนเร็วกว่า XGBoost และ CatBoost อย่างชัดเจน
