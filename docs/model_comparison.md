# รายงานวิเคราะห์และเปรียบเทียบโมเดล (Model Comparison Report) สำหรับ NIDS

เอกสารฉบับนี้สรุปผลลัพธ์จากการปรับจูนพารามิเตอร์ (Hyperparameter Tuning) ใหม่อย่างรัดกุม โดยปราศจากปัญหาข้อมูลรั่วไหล (Data Leakage) และการประเมินประสิทธิภาพผ่าน 5-Fold Stratified Cross-Validation เพื่อคัดเลือกโมเดล Machine Learning ที่ดีที่สุดสำหรับเป็น **Baseline Model** ของระบบ Network Intrusion Detection System (NIDS)

## 📌 วัตถุประสงค์ในการวิเคราะห์
เนื่องจากชุดข้อมูลมีการกระจายตัวของคลาสที่ไม่สมดุล (Class Imbalance) และชุดทดสอบ (`KDDTest+`) ประกอบด้วยการโจมตีรูปแบบใหม่ๆ (Zero-Day Attacks) ที่ไม่เคยปรากฏในชุดฝึกฝน (`KDDTrain+`) การวัดผลจึงเน้นที่:
- **Recall (Macro):** ต้องสูงที่สุดเท่าที่เป็นไปได้ เพื่อป้องกันมิให้ระบบหลุดรอดหรือปล่อยผ่านการโจมตี (False Negatives ต่ำ)
- **F1-Macro:** ค่าเฉลี่ยฮาร์มอนิกระหว่าง Precision และ Recall เพื่อดูความสมดุลและความครอบคลุมของโมเดล
- **ความทนทานต่อ Zero-Day:** โมเดลที่ดีต้องไม่ Overfit กับข้อมูลฝึกฝน และต้องมี Performance ที่ดีในชุด KDDTest+ 

---

## 🏆 1. สรุปพารามิเตอร์ที่ดีที่สุด (Best Configurations)

โมเดลทุกตัวผ่านการทำ Train/Validation Split บนข้อมูลฝึกฝนล้วนๆ เพื่อหาพารามิเตอร์ที่ดีที่สุด ป้องกันการเกิด Hyperparameter Leakage ได้ผลลัพธ์พารามิเตอร์ที่ดีที่สุดดังนี้:

| Model | Best Configuration (จากฝั่ง Validation) |
| :--- | :--- |
| **XGBoost** | `n_estimators: 100, max_depth: 10, learning_rate: 0.1, scale_pos_weight: 10` |
| **Random Forest** | `n_estimators: 100, max_depth: None, min_samples_split: 2, class_weight: 'balanced'` |
| **LightGBM** | `n_estimators: 200, max_depth: -1, learning_rate: 0.1, is_unbalance: True` |
| **CatBoost** | `iterations: 150, depth: 8, learning_rate: 0.05, auto_class_weights: 'Balanced'` |

## 🛡️ 2. ประสิทธิภาพบนการทำ 5-Fold Cross-Validation (บนชุด KDDTrain+)

การทำ CV ครั้งนี้ใช้เพื่อตรวจสอบ **"เสถียรภาพ" (Stability)** และ **"ขีดจำกัดความแม่นยำ"** บนการกระจายข้อมูล (Data Distribution) เดียวกัน:

| Model | Accuracy | Precision (Macro) | Recall (Macro) | F1-Macro | Fit Time (Avg) |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **LightGBM** | **0.9990** (±0.0001) | **0.9993** (±0.0001) | 0.9987 (±0.0003) | **0.9990** (±0.0001) | ~19.16s |
| **XGBoost** | 0.9988 (±0.0002) | 0.9986 (±0.0003) | **0.9989** (±0.0003) | 0.9987 (±0.0002) | ~17.45s |
| **Random Forest** | 0.9987 (±0.0002) | 0.9991 (±0.0001) | 0.9981 (±0.0003) | 0.9986 (±0.0002) | **~15.79s** |
| **CatBoost** | 0.9983 (±0.0002) | 0.9989 (±0.0002) | 0.9974 (±0.0005) | 0.9982 (±0.0002) | ~33.33s |

**ข้อสังเกตจาก CV:**
- บนข้อมูลที่หน้าตาคล้ายกัน (Train Distribution) กลุ่มโมเดล Tree-based ทุกตัวทำคะแนน F1-Macro ทะลุ 0.99 ได้ทั้งหมด
- **XGBoost** ครองแชมป์ด้าน **Recall** (0.9989) ปล่อยให้การโจมตีรอดสายตาไปได้น้อยที่สุดบนข้อมูลเก่า
- การแกว่งของคะแนน (Standard Deviation: ±) ของโมเดลทุกตัวต่ำมากในระดับ 0.0001 - 0.0003 แปลว่าโมเดลมีความเสถียร ไม่ขึ้นอยู่กับการสุ่มข้อมูล

## 🚨 3. ประสิทธิภาพเมื่อเผชิญข้อมูลจริง (Zero-Day Evaluation บน KDDTest+)

เมื่อนำโมเดลที่ดีที่สุดมา Retrain เต็มรูปแบบ และทดสอบกับชุด **KDDTest+** ซึ่งแฝงไปด้วยการโจมตีรูปแบบใหม่ที่มันไม่เคยเรียนรู้มาก่อน (Zero-Day Attacks) นี่คือบททดสอบที่แท้จริง:

| Model | F1-Macro | Recall (Macro) | Precision (Macro) |
| :--- | :---: | :---: | :---: |
| **XGBoost** | **0.8072** | **0.8272** | **0.8336** |
| **Random Forest** | 0.7866 | 0.8096 | 0.8220 |
| **LightGBM** | 0.7755 | 0.8004 | 0.8165 |
| **CatBoost** | 0.7706 | 0.7961 | 0.8135 |

> [!IMPORTANT]
> **บทสรุปผู้ชนะตัวจริง: XGBoost** 🏆
>
> หลังจากลบ Data Leakage ที่ทำให้ผลลัพธ์หลอกตาออกไป **XGBoost** พิสูจน์ตัวเองว่าเป็นโมเดลที่แข็งแกร่งและ **ทนทานต่อความเปลี่ยนแปลงของข้อมูล (Generalization) ได้ดีที่สุด** โดยทำคะแนนทิ้งห่างโมเดลอื่น ๆ กว่า 2-3% ในทุกมาตรวัด (F1, Recall, Precision) เมื่อต้องเจอกับการโจมตีแบบ Zero-Day

## 🔍 4. บทวิเคราะห์เชิงลึก (Deep-dive Analysis)

1. **ภาพลวงตาจาก Data Leakage เดิม:** 
ในรายงานฉบับก่อนหน้า LightGBM เคยได้คะแนนสูงถึง 0.86 ทว่าเกิดจากการที่โมเดลถูกชักนำด้วยผลลัพธ์บน Test Set เมื่อแก้ไขกระบวนการให้ถูกต้อง (วัดผลจาก Validation Set) เราพบว่า LightGBM เกิดการ Overfit บนชุดฝึกฝนอย่างหนัก (F1-CV สูงถึง 0.9990) แต่กลับทำผลงานบนชุด Zero-Day ได้แย่กว่าที่ควร (F1 เหลือ 0.7755)

2. **ความแข็งแกร่งของ XGBoost:**
พารามิเตอร์ของ XGBoost ที่ถูกเลือก (`max_depth: 10`, `scale_pos_weight: 10`) ช่วยให้มันเรียนรู้โครงสร้างเชิงลึก (Deep Interactions) ของพฤติกรรมเครือข่าย โดยที่ยังคงน้ำหนัก (Weight) ให้กับการตรวจจับความผิดปกติ ส่งผลให้มันสามารถรับมือกับ Pattern ประหลาดๆ ใน `KDDTest+` ได้ดีกว่าตัวอื่นๆ อย่างชัดเจน 

3. **Random Forest เซอร์ไพรส์ในอันดับสอง:**
แม้เป็นอัลกอริทึมที่เรียบง่าย แต่ Random Forest ด้วย `class_weight='balanced'` สามารถ Generalize ได้ดีเป็นอันดับสอง (F1: 0.7866) เหนือกว่า Gradient Boosting อย่าง LGBM และ CatBoost แสดงให้เห็นว่าการใช้ Bagging Technique (สร้างต้นไม้แบบสุ่มหลายๆ ต้นแล้วโหวต) ช่วยลด Variance และป้องกัน Overfitting ในโจทย์ที่ Test Set ดิ้นไปจาก Train Set ได้ดีเยี่ยม

4. **ระยะเวลาการประมวลผล (Resource Efficiency):**
- **Random Forest** เป็นแชมป์ด้านความเร็ว (Fit time ~15.8 วินาที)
- **XGBoost** เร็วรองลงมาอย่างสูสี (~17.5 วินาที) ถือว่าคุ้มค่ามากเมื่อเทียบกับความแม่นยำที่ได้รับ
- **LightGBM** ใช้เวลา ~19.1 วินาที
- **CatBoost** ช้าที่สุด (~33.3 วินาที) และยังให้ผลลัพธ์บน Zero-day น้อยที่สุดในกลุ่ม

## 🚀 5. ข้อเสนอแนะและก้าวต่อไป (Next Steps)

1. **อัปเดตระบบหลักไปใช้ XGBoost:** แนะนำให้ใช้พารามิเตอร์ชุด `{'n_estimators': 100, 'max_depth': 10, 'learning_rate': 0.1, 'scale_pos_weight': 10}` เป็นโมเดล Baseline หลักของโปรเจกต์นับจากนี้ 
2. **การทำ Feature Engineering:** เนื่องจากประสิทธิภาพรวมบน Test Set ยืนพื้นอยู่ที่ประมาณ 80-82% เราควรหันไปมุ่งเน้นที่ตัว **ข้อมูล (Data)** การทดลองเพิ่ม Feature รูปแบบใหม่ (Interaction term, Time-window features) จะมีศักยภาพในการดึงคะแนนขึ้นได้มากกว่าการฝืนจูนพารามิเตอร์ 
3. **พิจารณา Ensemble:** เนื่องจาก XGBoost เก่งด้านการลด Bias และ Random Forest เก่งด้านการลด Variance ในอนาคตเราอาจนำสองตัวนี้มาผสมกันด้วยเทคนิค Voting Classifier เพื่อความเสถียรที่มากยิ่งขึ้น
